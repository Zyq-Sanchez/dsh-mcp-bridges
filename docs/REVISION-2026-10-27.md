## Goal → implementation

| Goal | Implementation |
|---|---|
| 1. Session reuse by task binding | `lib/registry.mjs` persists `task_id → {goal, project, session_id, status, summary, turns, usage}` in `state/tasks.json`; `dsh_run` without `task_id` always creates a new task + session (cwd auto-reuse removed); same `task_id` continues the bound session; `fresh: true` replaces it; `usage_update` ratio ≥ `DSH_BRIDGE_HANDOFF_RATIO` opens a new session with a `[handoff]` prompt prefix |
| 2. Retrieval cost | O(1) `registry.get(task_id)`; `dsh_tasks` returns ≤5 (default 3) compact candidates by query/project, never transcripts; no full-history scan |
| 3. Existing sidebar / resume | ACP client now calls `session/resume` (DSH implements resume, not load; requires matching cwd) and `session/list`; `dsh_continue(session_id)` attaches an existing session; bridge restart resumes by `task_id`; no new UI |
| 4. Fewer round trips | summary default 900 → **1500** chars with `## 改动/## 验证/## 未解决/## 下一步` guidance; `lib/results.mjs` streams `agent_message_chunk` to disk independently of the 8k summary buffer, so `dsh_read` always serves the complete text (failure/timeout keeps the partial file as the handle) |
| 5. Execution control | `lib/deadline.mjs`: one budget covers ACP startup + initialize + session/new/resume + queue wait + prompt; default 900 s, cap 3300 s (host `tool_timeout_sec` is 3600); per-session queue with per-request removal; only a **running** prompt gets `session/cancel`; one automatic retry only for process/protocol errors **before** the prompt; permissions stay fail-closed |

Progress / observability | `session/update` → MCP `notifications/progress` when `_meta.progressToken` is present (throttled); `logs/calls.jsonl` per delegated call with `bridge_ms`, `received_at`, `phases {ensure_ms, resume_ms, session_new_ms, queue_ms, prompt_ms, retry}`, `summary_chars`, `full_chars`, progress counts; `test/compare-latency.mjs` joins caller-side and bridge-side timing (offline fake ACP) |

## Behaviour changes the caller will notice

- `dsh_run` reply now contains `task=<id>` (in addition to `session=<id>` and the
  `full output` handle). Follow-ups should use `dsh_continue(task_id=…)`;
  `session_id` still works.
- Header markers: `[new]`, `[reused]`, `[resumed]`, `[handoff]`.
- New tool `dsh_tasks` for compact old-task lookups.
- Summary cap is 1500 chars by default; the full text is always stored.
- Emitting a `_meta.progressToken` on `tools/call` now yields
  `notifications/progress` messages.
- `logs/calls.jsonl` and `state/tasks.json` are created on first use (default
  under `warm-session/`, all gitignored).
